# اختبارات الحمل — معرض رقية

تعمل على **نسخة محلية كاملة** (PostgreSQL + PostgREST حقيقيان + كل الترحيلات + ٢٠٠٠ منتج تجريبي)، ولا تلمس الإنتاج أو Supabase أبداً.

```bash
export RQ_K6=/path/to/k6 RQ_POSTGREST=/path/to/postgrest
python3 tests/load/run.py        # ~9 دقائق — النتائج في tests/load/results/latest.md
```

| السيناريو | ماذا يحاكي |
|---|---|
| browse | ٥٠٠ زائر في نفس الوقت، كل منهم: الرئيسية ← قسم ← منتج ← أحياناً بحث وسلة، مع ٢–٦ ثوانٍ تفكير بين الخطوات. مباشرة إلى API بلا CDN (أسوأ حالة لقاعدة البيانات). |
| spike | ٣٠٠ زبون يضغطون «اطلب» في اللحظة نفسها على قطعة متوفر منها ١٠٠، وكل واحد يعيد الإرسال (ضغطة مزدوجة). بعدها: فحص عدم البيع الزائد وعدم تكرار الطلبات. |
| mixed | ٥٠٠ زائر + ٥ طلبات في الثانية معاً. |
| stress | ١٠٠ زائر بلا وقت تفكير — الحد الأقصى لهذا الجهاز. |

على الإنتاج (بعد موافقة المالك فقط، وعلى staging أولاً): نفس سكربتات k6 مع `BASE=https://<ref>.supabase.co/rest/v1` و`JWT=<المفتاح العام>` — لكن حدود الإغراق في قاعدة البيانات (٦ طلبات/١٠ دقائق لكل عنوان، و٣٠٠ طلب/١٠ دقائق للمتجر كله) سترفض اختبار الطلبات عمداً؛ تُرفع مؤقتاً على staging فقط.
